## **b. 핵심 가치 제안** (기존 서비스 대비 차별점)

---

목적형 사용자가 구매 결정에 필요한 핵심 정보(사이즈·비용 등)를, 긴 상세페이지를 헤매지 않고 **원하는 항목만 골라 즉시 도달**하도록 한다. 나아가 셀러가 "상세설명참조"로 비워둔 정보까지 AI로 채워, **정보가 있든 없든 일관된 탐색 경험**을 제공한다.

- **웹의 방치된 문제를 푼다.** 오늘의집은 앱에는 AI 요약으로 "정보가 많아 찾기 어렵다"는 문제에 대응했지만, 웹은 여전히 방치돼 있다. 우리는 이 웹의 공백을 메운다. (조사 시점 기준 웹 미적용)
- **비어 있던 정보를 채운다.** 셀러가 "상세설명참조"로 비워둔 정보도 AI로 추출·보완해, 셀러 입력 여부에 좌우되던 정보 격차를 줄인다. (이번 MVP는 예시 시연 수준)
- **읽어주는 게 아니라 찾아가게 한다.** 앱 AI 요약이 정보를 요약해 보여주는 방식이라면, 우리는 유저가 원하는 항목(크기·색상 등)을 골라 그 정보 위치로 직접 도달하게 해 탐색 주도권을 유저에게 준다.

# 6. 솔루션 가설

<aside>
🔥

> **AI로 상품 고시 정보의 부실한 정보를 채우고 탭·스크롤*로 정보를 쉽게 찾게 하면**, 목적형 유저가 구매에 필요한 핵심 정보(사이즈 등)가 콘텐츠 중심 구조에 묻혀 찾기 어려운 문제를 해결해 **정보 도달 시간이 40% 단축할 것**이다.
> 

*스크롤 애니메이션은 instant로 즉, 타겟 정보 영역으로 순간이동.

</aside>

**근거 :** 쉽게 찾게 하면 탐색 부담이 줄어들고 결정이 쉬워지기 때문에 구매 전환이 오른다.

- **쉽게 찾게 하면(탭·스크롤) → 탐색 부담이 줄고 결정이 쉬워진다**
    - Baymard·NNG 사용성 연구: 무한 스크롤은 목적형 유저에게 마찰을 유발함. 본 항목으로 되돌아가기 어렵고 비교가 힘들어 구매 완료에 필요한 행동이 어려워짐. 반면 영감·발견 모드 브라우징엔 잘 맞음.
    → [https://medium.com/design-bootcamp/infinite-scroll-vs-pagination-in-ecommerce-ux-who-wins-the-battle-for-conversion-753dfcece8d3](https://medium.com/design-bootcamp/infinite-scroll-vs-pagination-in-ecommerce-ux-who-wins-the-battle-for-conversion-753dfcece8d3)
    - NNG + 2024년 동료심사 연구: 상단 고정(sticky) 내비게이션이 과제 수행 시간을 유의미하게 단축시키고, 사용자가 탐색이 더 쉽다고 일관되게 응답함. 헤더 요소의 발견 가능성과 사용 확률도 높아짐.
    → [https://lovable.dev/guides/website-navigation-best-practices-that-convert](https://lovable.dev/guides/website-navigation-best-practices-that-convert)
- **결정이 쉬워지면 구매 전환이 오른다**
    - 정보를 못 찾으면 마찰과 불신이 생겨 이탈률↑·전환율↓로 이어짐. UX 주도 기업은 마찰을 줄여 경쟁사보다 전환에서 4.6배 앞섬.
    → [https://www.invespcro.com/blog/the-role-of-user-experience-in-conversion-optimization/](https://www.invespcro.com/blog/the-role-of-user-experience-in-conversion-optimization/) · [https://medium.com/@dollyborade07/e-commerce-ux-breakdown-can-better-product-pages-drive-25-higher-conversions-e5b387352a51](https://medium.com/@dollyborade07/e-commerce-ux-breakdown-can-better-product-pages-drive-25-higher-conversions-e5b387352a51)
    - "사이즈 차트를 못 찾아 불확실성 때문에 장바구니를 포기했다"가 실제 사용성 인사이트로 제시됨
    → [https://www.ecorn.agency/blog/web-site-usability-study](https://www.ecorn.agency/blog/web-site-usability-study)

| 상세정보 탭 |   • 상세정보 탭 버튼에 마우스를 올릴 시 호버 메뉴(색상, 크기, 주요 소재, 구성품, 배송/설치비용)가 하단에 표시

  • 한 항목의 정보가 옵션(사이즈·색상 등)별로 페이지 내 여러 위치에 나뉘어 있을 수 있어, 클릭 동작이 매핑된 위치 개수에 따라 분기함.
      ◦ 위치 1개: 클릭 시 곧바로 해당 위치로 스크롤 이동
      ◦ 위치 2개 이상: 클릭 시 스크롤하지 않고 항목 버튼 바로 아래에 드롭다운을 펼침. 각 위치를 옵션 이름으로 구분해 나열하며(예: '크기' → "킹", "퀸"), 드롭다운 항목 클릭 시 해당 정보가 있는 위치로 스크롤 이동
  • 항목: 색상, 구성품, 주요 소재, 크기, 배송·설치비용 | **Must Have** |
| 비교 지원 |   • 콘텐츠에서 발견한 여러 후보를 한 화면에 나란히 모아 비교할 수 있는 비교 기능

  1. 침대 A, B, C, D에 대한 순위를 정해주세요.

| 탭의 시각적 발견성 부족 | 사용자가 기능을 충분히 인지할 때까지 **'NEW'** 배지 등으로 시각적으로 강조하고, 이후 일반 유저 대상 A/B 테스트를 진행 |
| 상세정보 탭의 클릭 가능 여부를 인지하기 어려움 | 호버메뉴에 “상품정보고시” 버튼 추가 후 A/B 테스트를 진행 |

# **13. 향후 과제 - 내 비교함(상품 비교 기능)**

## a. 배경 : 왜 이번 MVP에서 제외했는가

---

1. 구매에 필요한 핵심 정보(사이즈 등)가 콘텐츠 중심 구조에 묻혀 찾기 어렵다
2. 같은 카테고리 내에서 비교 중인 여러 제품의 정보가 쌓이면 기억·정리·비교하기 힘들다
- 이번 MVP(2주)는 개발 리소스와 검증 범위를 고려해 **문제(1)만 우선 해결**했다. 상세정보 네비게이션(sticky 탭 + 호버 항목 리스트 + 클릭 시 자동 스크롤)이 그 결과물이다.
- 문제(2)를 푸는 비교 기능은 개발 규모가 크고, 문제(1)이 먼저 검증되지 않은 상태에서 함께 진행하면 두 기능 모두 완성도가 떨어질 위험이 있어 **백로그로 분리**했다.

## b. 목표 : 이 로드맵이 궁극적으로 노리는 것

---

1. 이번 MVP의 성공지표는 정보 도달 시간·클릭 수 단축(1차 KPI)에 머물렀고, 구매 전환율은 측정 불가능해 2차 지표(방향성 목표)로만 남겨줬다. **비교 기능은 문제(1) 해결만으로는 닿지 못하는, 실제 구매 결정 단계의 마찰을 없애 장바구니 담기·구매 전환에 직접 기여하는 것을 목표로 한다.**
2. 정보 접근이 쉬워져도(문제1 해결), 후보가 여러 개면 유저는 여전히 “이 중 뭐가 나은가”를 스스로 기억하고 비교해야 한다. 이 마찰이 남아있는 한, 유저는 확신 없이 이탈하거나 결정을 미룰 수 있다. [Baymard Institute](https://baymard.com/blog/provide-comparison-features) 연구에 따르면 유저는 여러 상품 페이지를 오갈 때 이전 정보를 기억한 채 이동해야 해 번거로움을 느끼고, 이는 적합한 상품을 놓치기거나 배제 판단에 과도한 시간을 쓰는 결과로 이어진다. 이 마찰을 제거하는 것이 문제(1) 해결 다음 단계의 목표다.

## c. 단계별 로드맵

---

| **단계** | **기능** | **설명** | **근거** |
| --- | --- | --- | --- |

| 2단계 | 비교 목록 저장 유지 | 담아둔 후보가 세션이 끝나도 유지되어, 여러 번에 걸쳐 재방문하며 비교를 이어갈 수 있음 | [NN/G](https://www.nngroup.com/articles/saving-scroll-position/) - 페이지 파킹은 세션이 끊기면 무력화되며, 유저가 며칠·몇 주 후 재방문 시 어디까지 봤는지 기억 못 하는 문제 발생. 이커머스에서 유저는 여러 상품을 클릭해 사이즈·가격·리뷰를 비교하는 게 전형적 행동 |
| 3단계 | 후보 간 차이 자동 계산 | 비교 목록에서 가격차·사이즈차를 자동 계산해 표시, 유저의 암산·대조 부담 제거 | 비교 도구가 있어도 스펙 대조 자체를 유저가 직접 해야 하면 결정 난이도가 남는다는 문제의식**(1단계 근거의 확장)** |
| 4단계 | 콘텐츠 다건 담기 | 집들이 콘텐츠 하나에 태그된 여러 상품을 한 번에 비교 목록으로 담기 | [오늘의집 패키지 할인(다품목 동시 구매 설계)](https://store.ohou.se/packages/landing) |
