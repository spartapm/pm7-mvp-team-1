생성일: July 27, 2026 11:43 PM

# 1. 기능 배경

---

- 핵심 타겟
    
    **이사·자취·신혼 등 특정 목적을 가지고 오늘의집에 방문해 가구를 구매하려는 목적형 사용자**
    
    - 이사, 자취, 신혼 유저는 쇼핑 형태나 예산 등에서 차이가 있으나, 이번 개선에서는 전반적인 탐색 경험을 목표로 특정 목적을 설명하기 위함임.
    
    **상품의 종류는 정했지만 정확히 어떤 제품을 살지는 정하지 못한 사용자**
    
    - 쿠팡 사용자: “슈퍼싱글 매트리스가 필요해.”
    - 네이버쇼핑 사용자: “A브랜드 슈퍼싱글 매트리스 최저가를 찾아야지.”
    - 오늘의집 사용자: “원룸에 놓을 침대가 필요한데, 어떤 침대가 내 방에 어울리고 공간 활용에 좋을까?”
- 페인 포인트
    
    **구매에 꼭 필요한 정보(사이즈 등)가 콘텐츠에 묻혀 찾기 어렵다.**
    
    - 가구 사이즈 정보가 상세페이지 상단이 아니라 아래쪽·중간에 있어서 제일 궁금한 정보를 보려고 스크롤을 한참 내려야 한다는 리뷰(사용자 10명이 해당 리뷰가 유용하다고 반응)
- 문제 정의 및 솔루션 가설
    
    **문제 현상**: 구매에 꼭 필요한 정보(사이즈 등)·모드가 콘텐츠에 묻혀 찾기 어렵다.
    
    **핵심 문제 정의**: 
    
    - **누가**: 이사·자취·신혼 등 특정 목적으로 오늘의집을 찾아, 살 상품의 종류는 정했지만 구체적으로 어떤 제품을 살지는 정하지 못한 목적형 사용자가
    - **어떤 상황에서**: 여러 후보 제품을 비교하며 "내 상황(공간·예산·용도)에 가장 맞는 것"을 고르려 할 때
    - **무엇 때문에**: 구매 결정에 필요한 핵심 정보(사이즈·비용·사양)가 콘텐츠 중심 구조에 묻혀 찾기 어렵다. + 현재 제공되는 가이드라인의 정보가 부실하다.
    
    **이 문제가 중요한 이유**: 
    
    - **어떤 손해를 겪는가**: 비교·결정 과정에서 인지적 부담을 느끼고 헤매다가, 구매로 연결되지 않는다.

# **3. 핵심 기능 정의**

- **기능명**: AI를 활용한 이미지 내 정보 영역 자동 스크롤, 상품정보고시 내용 보강
- **기능 한 줄 설명**: 사용자가 상품의 카테고리의 주요 정보에 빠르게 접근할 수 있다.
- **이 기능을 핵심으로 선정한 이유**: 목적형 유저가 구매에 필요한 핵심 정보(사이즈 등)가 콘텐츠 중심 구조에 묻혀 찾기 어려운 문제를 해결하기 위함

<aside>
📌

> **MVP 범위**
> 
- 카테고리 페이지의 구현은 대분류 **카테고리 2개(침대, 매트리스) 내 하위 카테고리 별 5개 상품 목록 구현은 필수**, 나머지 요소의 구현은 Nice To Have.
- 가구 - 침대, 매트리스 카테고리의 하위 카테고리에 한정하여 **각 5개의 상품**(총 25개)을 MVP로 구현한다.
- 상품 상세 페이지에서 상단 탭 바의 **상품 설명, 상세정보**를 제외한 탭 버튼은 표시만 하고, 동작은 구현하지 않는다.
- 장바구니/구매 기능 - UI만 구현, 기능은 구현하지 않음.
</aside>

# **4. User Flow**

| **No** | **요소** | **상세 설명** | **비고** |
| --- | --- | --- | --- |
| 1 | 상품 상세 페이지 진입 | • 유저가 카테고리 페이지에서 상품 카드 클릭을 통해 상품 상세페이지 진입.
• 상품 상세페이지 상단에 상단 탭 바의 ‘상세정보’ 탭이 새로 추가된 구조 | • AS-IS와 동일한 진입 경로
• 튜터님 이 노드부터 바뀝니다!
 |
| 2 | 상세정보 탭에 커서 클릭 | • 유저가 상단 탭 바의 ‘상세정보’ 탭에 마우스를 클릭하면(호버) 하단에 호버 메뉴가 노출됨 | • AS-IS의 “스크롤 반복 탐색”을 대체하는 지점.
• 정보 위치를 몰라도 탭 하나로 전체 항목을 한눈에 확인 가능. |
| 3 | 타겟 정보 버튼 클릭 | • 상세정보 탭 클릭 or 노출된 호버 메뉴 중 원하는 항목을 클릭
예) 사이즈 클릭 | • 클릭 시점의 항목명이 4번(자동 스크롤)의 타겟 좌표와 매핑되어야 함. |
| 4 | 타겟 정보 영역으로 자동 스크롤 | • 클릭한 항목에 해당하는 정보가 있는 영역으로 화면이 자동으로 스크롤 이동. | • 유저의 수동 스크롤을 시스템이 대신 수행하는 구간.
• AS-IS엔 없던 신규 동작 |
| 5 | **타겟 정보 습득** | • 스크롤 이동이 완료된 화면에서 원하는 정보(사이즈 등)를 확인.
• 정보 도달까지의 시간/클릭 수(KPI 측정 대상) | • AS-IS의 3번과 대응되는 지점
• 두 버전 간 시간/클릭 수 비교가 이 노드에서 이뤄짐 |
| 6 | 추가로 습득할 정보가 있는가?(분기) | • 유저가 확인할 정보가 더 있는지 판단.
예: 2번(상세 정보 탭에 커서 올림)으로 회귀/아니오 : 7번(장바구니/구매 전환 혹은 이탈) | • 이게 AS-IS 대비 가장 큰 구조적 차이임 |
| 7 | 장바구니/구매 전환 혹은 이탈 | • 필요한 정보를 모두 확인했다고 판단되면 장바구니 담기/구매로 이어지거나, 과정 중 탐색 피로가 누적돼 이탈 | • AS-IS와 동일한 최종 상태
• 도달 과정의 마찰이 줄어든 만큼 전환 비중이 높아질 것으로 기대(2차 KPI 지표) |

이번 MVP에서 호버 메뉴의 항목 종류는 [색상, 크기, 주요 소재, 구성품, 배송/설치비용] 5개이다.

상품 별 JSON 파일의 imageInfoTags 값에 항목명을 키 값으로 참조한다.

- 항목의 locationCount 가 0인 경우 항목 버튼을 비활성화한다.
- 항목의 locationCount 가 1인 경우 항목 클릭 시 locations 내의 값을 참조해 바로 스크롤 이동한다.
- 항목의 locationCount 가 2 이상인 경우 클릭 시 드롭다운 메뉴를 표시하고, 드롭다운 메뉴의 항목은 locations의 값들을 참조해 생성한다.
- locations의 개별 요소들의 title을 참조하여 드롭다운 메뉴 항목을 생성하고, 이를 클릭할 시 지정된 위치로 스크롤 이동한다.
- 스크롤 이동 시, file 값을 참조하여 해당 파일명의 img 요소의 scrollY 값에 img 요소의 height에 yRatio를 반영한 값을 계산하여 해당 위치로 스크롤 이동한다.
